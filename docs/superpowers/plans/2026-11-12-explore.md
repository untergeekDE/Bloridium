# `bloridium explore` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Interaktives `bloridium explore`: sagt, welcher Iridium-Parameter als Nächstes am Panel zu drehen ist, nimmt die OS4-NRPN (Pid + Wert) auf, bucht sie in `docs/midi-maps/iridium_os4_cc_list.csv` + `recordings/explore_log.jsonl` – Datenbasis für OS4-.mimap und „Iridium als Editor für den Blofeld".

**Architecture:** Reine, hardwarefreie Logik in `bloridium/explore.py` (NRPN-Decoder-State-Machine, CSV-State, JSONL-Log); dünne MIDI-/Prompt-Schicht als `cmd_explore` in `bloridium/cli.py` (nutzt `midi.DEFAULT_PORTS["iridium"]` + `Synth.receive()`). Rein lesend – das Tool sendet kein MIDI.

**Tech Stack:** Python ≥ 3.10, mido (bestehend), pytest; macOS/CoreMIDI. Keine neuen Dependencies.

**Spec:** `docs/superpowers/specs/2026-11-12-explore-design.md` (genehmigt 2026-11-12; Builder-Check-Festlegungen siehe Spec „Builder-Check")

## Global Constraints

- Rein lesend: `explore` sendet **kein** MIDI (kein CC, kein PC, kein SysEx) – CC7=0-Stumm-Gefahr entfällt.
- CSV `iridium_os4_cc_list.csv`: bestehende 8 Spalten bleiben unverändert, neue Spalten nur angehängt (`NEW_COLUMNS`).
- NRPN-Dekodierung: `pid=(cc99<<7)|cc98`, `value=(cc6<<7)|cc38`; `cc99/98=127` und `cc121` resetten den State; `cc101/100` (RPN) ignorieren.
- Kanal strikt filtern (Default 0-basiert 5 = ch6 = Part 1, `--channel` override); fremde Kanäle weder dekodieren noch buchen.
- Exit-Codes: 0 ok, 1 Fehler, 2 Hardware nicht erreichbar (Port-Liste auf stderr) – wie bestehende CLI.
- Ausgabe Plain Text (Deutsch, wie bestehende CLI), `--json` für `explore --list`.
- Kein Live-MIDI in Tests (monkeypatch, tmp_path).
- macOS, Python ≥ 3.10; nur stdlib + mido + pytest.

## Review Focus

1. **Falscher Port/Kanal → leere Fänge** (DIN liefert evtl. kein Panel-NRPN; Part nicht auf ch6): dreistufige Diagnose beim leeren Fang (nichts empfangen / nur CC / NRPN auf anderem Kanal mit Kanal-Hinweis). Test: `test_explore_empty_capture_hints_and_stays`.
2. **Mehrere Pids in einem Fang** (z. B. Sound-Wechsel Pid 3113 mitten im Dreh): häufigster Pid gewinnt, min/max/last nur über Gewinner, alle Events ins Log. Test: `test_book_row_winner_pid`.
3. **Alte CSV ohne neue Spalten** (vor erstem Lauf): `load_cc_list` ergänzt leere Spalten, `save_cc_list` hängt an + legt `.bak` an. Test: `test_csv_roundtrip_appends_columns_and_bak`.
4. **NRPN-Reset mitten im Stream** (`cc99/98=127`, `cc121`): darf keinen Geister-Event erzeugen. Test: `test_decoder_reset_cases`.
5. **Tool sendet nichts** (Anti-Goal „rein lesend“): Session darf keine einzige Out-Nachricht produzieren. Test: `test_explore_session_sends_nothing` (FakeSynth zeichnet `send` auf).

```python
def test_decoder_mitschnitt_pid3113():
    from bloridium.explore import NrpnDecoder
    import mido
    d = NrpnDecoder()
    msgs = [mido.Message("control_change", control=c, value=v, channel=5)
            for c, v in [(99, 0x18), (98, 0x29), (6, 0x7F), (38, 0x7F)]]
    events = [d.feed(m) for m in msgs]
    assert [e for e in events if e] == [(3113, 16383)]  # (0x18<<7)|0x29, (0x7F<<7)|0x7F
```
